2. Development tools
2.1 Node.js
What is Node.js?

Node.js is a runtime environment that allows us to execute JavaScript outside a web browser.

Normally, JavaScript runs inside a browser such as Chrome. Node.js allows us to use JavaScript to build server-side applications, command-line tools and other programs.

Why are we using Node.js in SignalDesk?

We will use Node.js to run our Express backend. Later, the backend will handle authentication, customer feedback, database operations, AI processing and other application logic.

Check Node.js:
node -v


What does -v mean?

-v means version. This command displays the installed Node.js version.

2.2 npm
What is npm?

npm stands for Node Package Manager. It helps us install, manage and run JavaScript packages and project scripts.

A package is a reusable piece of code that developers can install instead of building everything from scratch.

For example, we installed Express using npm.
npm -v


This checks the installed npm version.
Why do we need npm?
Imagine we want to build an HTTP server. We could write a lot of low-level code ourselves, but Express provides useful functions and abstractions that make building the server easier.

npm allows us to install Express into our project.

2.3 Git
What is Git?

Git is a version-control system.

It tracks changes to files in a project over time. It allows developers to save snapshots of their code, inspect changes and return to previous versions when necessary.
Why do we need Git?
Suppose today your application works perfectly.

Tomorrow, you change 20 files and accidentally break the application.

With Git, if you have saved a previous commit, you can inspect or recover the earlier state.

Git helps us:
- Track code changes.
- Save checkpoints.
- Compare versions.
- Collaborate with other developers.
- Manage development branches.
Check Git:
git --version

We use it to:

- Open the terminal.
- Debug our applications.
- Manage project files.
We are using VS Code because it provides a convenient environment for developing React and Node.js applications.

9. Installing Express

This installs Express into our backend project.
What happens after installation?
npm:
1. Downloads the package.
2. Adds Express to the dependencies in package.json.
3. Installs the package inside node_modules.
4. Updates the package lock file.
What is package-lock.json?
package-lock.json records specific dependency versions and dependency details to help reproduce installations consistently.

We generally keep this file in Git.

10. Installing Nodemon
We ran:
npm install -D nodemon


What is Nodemon?
Nodemon is a development tool that monitors our server files.

When we modify the server code, Nodemon automatically restarts the backend.

Without Nodemon, we might need to stop and manually restart the server after every change.
What does -D mean?
-D means install the package as a development dependency.

Nodemon is primarily a development tool, so we install it as a dev dependency.

11. ES Modules
11.1 What are ES Modules?
ES Modules are a JavaScript module system.

They allow us to divide our code into separate files and import or export functionality.

For example:
import express from "express";


This imports Express.

We will use import and export throughout our SignalDesk backend.
11.2 What does "type": "module" mean?
In our backend package.json, we added:
"type": "module"


This tells Node.js to interpret JavaScript files in this package using the ES Module system.

It allows us to use:
import express from "express";


Instead of the older CommonJS style:
const express = require("express");


For SignalDesk, we will use ES Modules.

13. Understanding our first backend file
We created:

server/server.js

Code:
import express from "express";

const app = express();

app.use(express.json());

app.get("/api/health", (req, res) => {
  res.json({ status: "ok" });
});

const PORT = 5000;

app.listen(PORT, () => {
  console.log(`Server running on http://localhost:${PORT}`);
});


Now let's understand every line.
13.1 Import Express
import express from "express";


This imports the Express package.

Without importing Express, we cannot use Express functionality in this file.
13.2 Create an Express application
const app = express();


This creates an Express application instance.

We store it inside the variable app.

We use this application instance to configure:
- Routes.
- Middleware.
- Server behavior.
13.3 Middleware
app.use(express.json());


What is middleware?
Middleware is a function or processing layer that runs as part of handling an HTTP request.

Middleware can:
- Read request information.
- Modify request or response objects.
- Perform validation.
- Authenticate users.
- Log requests.
- Pass control to another middleware.
- End the request.
What does express.json() do?
It parses incoming JSON request bodies.

Imagine a frontend sends:
{
  "name": "SignalDesk"
}


The JSON middleware helps Express parse this JSON body so we can access the data through req.body in routes.

Today we added it as basic backend preparation.

14. HTTP
14.1 What is HTTP?
HTTP stands for Hypertext Transfer Protocol.

It is a protocol used for communication between clients and servers.

A client can send an HTTP request to a server.

The server processes the request and sends an HTTP response.

For example:
Browser
   ↓ HTTP Request
Express Server
   ↓ HTTP Response
Browser


Later, React will send HTTP requests to SignalDesk APIs.
14.2 HTTP methods
We introduced the GET method today.

Common HTTP methods include:
Method	Common purpose
GET	Retrieve information.
POST	Create or submit information.
PUT	Replace an existing resource.
PATCH	Update part of a resource.
DELETE	Delete a resource.

We will study these properly when building our APIs.

15. Routes
15.1 What is a route?
A route tells the backend how to handle a request for a particular HTTP method and URL path.

For example:
app.get("/api/health", (req, res) => {
  res.json({ status: "ok" });
});


This route handles GET requests to:
/api/health


15.2 Understanding app.get()
app.get("/api/health", (req, res) => {
});


app.get() registers a route for GET requests.

The first argument is the route path.

The second argument is the callback function that executes when a matching request arrives.
15.3 Understanding req
(req, res) => {
}


req means request.

It represents information about the incoming HTTP request.

Later, it can contain information such as:
- Request parameters.
- Query parameters.
- Request body.
- Headers.
15.4 Understanding res
res means response.

It is used to send a response back to the client.

For example:
res.json({ status: "ok" });


This sends JSON to the requesting client.
